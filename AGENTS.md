# Trast

macOS menu-bar utility that applies user-defined window sizes/positions to the focused window (Raycast "Create Command" style), plus a Spotlight-like launcher with app launching, clipboard history, and snippet expansion. Native Swift 6 + SwiftUI, built with Swift Package Manager only — no Xcode project, works with Command Line Tools.

## Commands

```bash
swift build                  # debug build (app + tests)
swift run TrastTests    # run the test harness (exits non-zero on failure)
Scripts/package_app.sh       # release build + Trast.app bundle (version from latest git tag)
Scripts/dev.sh               # debug build + bundle + relaunch app
Scripts/update.sh            # release build + install to /Applications + relaunch
Scripts/make_dmg.sh          # release build + drag-to-Applications DMG in dist/
Scripts/install.sh [--force] # copy Trast.app to /Applications
```

`dev.sh` launches the repo bundle's executable directly (`nohup …/MacOS/Trast &`), never via `open` — `open` registers the dev copy in LaunchServices, and a duplicate `com.trast.app` registration (repo + /Applications) makes Spotlight drop Trast from app search (Spotlight's app results are LaunchServices-backed, not from the metadata index). If Spotlight ever loses the app again: `lsregister -dump | grep "path:.*Trast.app"` to check for two entries, then `lsregister -u <repo copy>` and `lsregister -f /Applications/Trast.app`.

There is no `swift test` workflow: this machine has Command Line Tools only (no full Xcode). CLT ships neither XCTest nor a working Swift Testing runtime (test bundles build but the runner discovers zero tests), so tests live in the `TrastTests` executable target and run via `swift run TrastTests`.

## Layout

- `Sources/TrastCore/` — dependency-free logic: `WindowDimension`, `Anchor` (two-axis struct with per-axis `keep` for move-style commands; decodes legacy flat strings like `"topLeft"`), `WindowCommand` (+ `seeds`, + `migratingLegacyCommands`), `LayoutEngine` (pure frame math + `frameForNextDisplay` for multi-display moves), `FuzzyMatch`, `TrastURL` parsing, `Snippet` (model: id, name, keyword, content, enabled; custom Codable with defaults for missing fields), `Note` (scratchpad note: id, text, createdAt, updatedAt, custom Codable with defaults; `excerpt` — one-line list preview — pure and tested), `ChatMessage`/`ChatDiscussion` (AI chat data; custom Codable with defaults), `TextTransform` (case transformations for the Text Transformer tool: upper/lower/title/sentence/camel/pascal/snake/kebab/constant/toggle — pure word-splitting with camel-hump and acronym boundaries, tested), `SavedColor` + `ColorFormats` (Color Picker model: hex string is truth, pure rgb/hsl conversions — tested; AppKit stays out of Core), `Calculator` (pure launcher-query parser + `MathEvaluator`; see the Calculator note below), `AppSettings`. All public API — consumed by both the app and tests.
- `Sources/Trast/` — app target: AX layer (`Accessibility`, `WindowManipulator`), `CommandApplier` (+ `RestoreStore`; intercepts the `nextDisplay` action before the normal LayoutEngine path to cycle `NSScreen.screens`), `CommandStore` (versioned JSON at `~/Library/Application Support/Trast/commands.json`; v2 = `{version, commands}`, legacy bare arrays migrate via `WindowCommand.migratingLegacyCommands`, which preserves IDs of name-matched commands so hotkeys survive), `AppShortcutStore` (versioned JSON at `~/Library/Application Support/Trast/appShortcuts.json`; `AppShortcut.Kind` = `app`, `url`, or `folder`), `ConfigPorter` (export/import combined JSON of both stores), `HotkeyManager`, menu bar + settings UI, `LauncherController`/`LauncherView`/`LauncherViewModel` (Spotlight-style launcher; borderless non-activating `NSPanel`; items grouped into Commands / Actions / Shortcuts / Applications / Trast sections; `LauncherAction` enum for app-level actions like Settings, Clipboard History, Check for Updates, Quit), `HUD` feedback, `URLDispatcher`, `ClipboardMonitor`/`ClipboardStore` (clipboard history; the launcher's Clipboard tab is the only UI for it), `SnippetStore`/`SnippetExpander` (snippet expansion via CGEvent tap), `HyperkeyEngine` (Caps Lock → ⌃⌥⇧⌘ hyper key), `ExchangeRateStore` (ECB rates for launcher currency queries; see the Calculator note below). The `Launcher/` directory also contains `UsageTracker` (persists recency ordering in UserDefaults key `launcherUsageLog`). The launcher has a Scratchpad category (editor mode instead of search + results; multiple notes via `NotesStore` — see the Scratchpad notes note below; the local key monitor in `LauncherController` lets Return/arrows/typing reach the editor and intercepts Esc, Tab, and ⌘N; a persistent notes sidebar (`LauncherView.notesSidebar`) sits beside the editor — the panel widens to 840 for the sidebar tools (`LauncherController.panelWidth(for:)`)). `HotkeyManager.openScratchpad` opens the launcher on the Scratchpad tab (toggle via `LauncherController.showScratchpad`, same shape as `showClipboard`); its recorder and a clear button live in the Scratchpad settings tab (`ScratchpadSettingsView`).
- Commands carry `isDefault` (seeds; sidebar "Defaults" section, restorable via `restoreDefaults()`) and `showInMenuBar` (menu bar only lists pinned commands and shortcuts; toggle in the editor, indicator in the sidebar). New custom commands are pinned by default. `AppShortcut` also has `showInMenuBar` (same Codable default-`false` shape); `AppShortcutStore.pinnedShortcuts` feeds the menu bar's Shortcuts submenu, and `AppShortcutStore.add` pins new shortcuts by default (stored shortcuts from before this field decode unpinned).
- **CI**: `.github/workflows/release.yml` builds/tests/DMGs on `v*` tag push and attaches the DMG to a GitHub Release. CI imports the signing certificate from repo secrets (`MACOS_SIGNING_P12` = base64 p12, `MACOS_SIGNING_PASSWORD` = export password) and signs with the stable identity — without the secrets it falls back to ad-hoc, which resets the Accessibility grant on update.
- **SPM resource bundles in packaged apps**: dependency packages with resources (KeyboardShortcuts) get a `Bundle.module` accessor that only checks the .app ROOT (codesign rejects placing bundles there) and an absolute path baked at build time. `package_app.sh` copies the bundles to `Contents/Resources/` and patches the baked path in the binary to `/Applications/Trast.app/Contents/Resources/<bundle>`, padding with path-safe slashes to preserve the baked string length (Swift literals are pointer+count, so the replacement must be same-length). Without the patch, packaged apps crash on any hotkey Recorder (Settings > General).
- **Updates**: `UpdateChecker` (app target) queries `https://api.github.com/repos/jeksn/trast/releases/latest` — **update the `repo` constant when the GitHub repo is created/renamed**. Compares via `VersionCompare` (Core), offers download-and-install (DMG asset → hdiutil → copy to /Applications → relaunch) or opening the release page. Bundle version comes from the latest git tag (`package_app.sh`), so tag releases `vX.Y.Z`.
- `Tests/TrastTests/` — custom harness (`TestRunner` + suite files + `main.swift`).

## Notes / gotchas

- **KeyboardShortcuts is pinned to exactly 1.10.0.** Newer 3.x uses SwiftUI `@Entry`/`#Preview` macros whose plugin dylibs (`SwiftUIMacros`, `PreviewsMacros`) do not ship with CLT — builds fail. Also, this environment's GitHub mirror only exposes tags up to v1.10.0.
- `onKeyUp` handlers APPEND (never replace): each command registers exactly once per UUID (`HotkeyManager.registeredCommandIDs`); handlers resolve the command dynamically from the store at fire time, so stale registrations are harmless no-ops. Deleting a command clears its shortcut via `KeyboardShortcuts.setShortcut(nil, for:)`.
- Offset semantics match Raycast: positive X offset moves right, **positive Y offset moves DOWN** (screen convention; the engine subtracts in Cocoa's bottom-left coordinates). Percent sizes/anchors/offsets are relative to `visibleFrame` inset by the global edge gap.
- `AppDelegate` registers the `trast://` URL scheme via `NSAppleEventManager` kAEGetURL. The event class/ID and direct-object keyword are hard-coded FourCharCode literals (`0x4755524C` = 'GURL', `0x2D2D2D2D` = '----') to avoid Carbon import issues with CLT.
- `WindowManipulator` uses the private `_AXUIElementGetWindow` (dlsym'd from ApplicationServices) to key restore geometry by CGWindowID; falls back to `pid-title` keys. Same approach as Rectangle/Loop.
- AX coordinates are top-left origin, NSScreen bottom-left; conversion helpers live in `WindowManipulator` (primary screen height based).
- Settings is a custom `Window` scene (id `settings`, title "Trast"), not the SwiftUI `Settings` scene — the `showSettingsWindow:` selector is unreliable in menu-bar apps on newer macOS. The open sequence lives in `SettingsWindow.open(_:)` (activate, `openWindow(id:)`, re-activate, order front). The Launcher and menu bar both open Settings through it: the menu bar calls it directly, and the Launcher posts `.openSettings`, observed by `StatusBarLabel` (the MenuBarExtra label view — the `.menu`-style extra's content is only instantiated while the menu is open, so observing from `MenuContent` never fired when the menu was closed).
- Settings uses a `NavigationSplitView` with a left sidebar (General, Window, Commands, Shortcuts, Snippets, Clipboard). Commands, Shortcuts, and Snippets use `HSplitView` for their sub-sidebar + detail; General, Window, and Clipboard use a grouped `Form`.
- The launcher panel is borderless (`.borderless` + `.nonactivatingPanel`) so the target app stays frontmost; the target window is captured when the panel opens. Panel height is dynamic (grows/shrinks with results via a Combine subscription on `viewModel.objectWillChange`); large jumps (mode switches) animate (`NSAnimationContext`, 0.18s easeInOut, matching `LauncherViewModel.modeAnimation`) while small deltas (result rows) snap — an instant `setContentSize` of a large delta lets the window's material layer draw square corners for a frame before SwiftUI re-applies the rounded-corner mask, and animating every keystroke delta restarts easeInOut from mid-flight frames, which stutters. `resizePanelToFit` also skips calls whose target frame is unchanged (`lastTargetFrame`) for the same reason, and pixel-aligns size + origin. **Resize ordering invariants** (the "tool hotkey opens a dead bare search box" bug): (a) the async observer pass can measure `fittingSize` for the PRE-change layout (SwiftUI applies the state change a turn later), so (b) the signature cache is only committed once a pass produced a NEW frame — a same-frame measurement with a new signature returns "ambiguous" and the observer re-checks once after the layout settles; caching the new signature with the old frame made every later pass skip and left the panel stuck at the old height for good, and (c) `show(_:)` applies the target category (tool hotkeys) BEFORE the sync resize so the open measures the final content — sizing the reset state first and switching category via `DispatchQueue.main.async` re-introduced the race, and (d) the sync resize itself can still measure the PRE-change layout when the panel already existed (the hosting view hadn't applied the reset/category switch yet — the "clipboard hotkey opens on a clipped empty search box" symptom), so `show(_:)` queues one forced re-measure (nils `lastLayoutSignature`) on the next turn with the settled layout. Background is the material itself — `.thickMaterial` in dark mode (darker, Spotlight-like, keeps its own translucency), `.regularMaterial` in light mode (a darkening overlay reads as flat grey there and flattens the blur); slight-transparency toggle (`launcherSlightTransparencyKey`, default on = 85% opacity, off = fully opaque — the old opacity slider is gone). The content width is per-category (`LauncherViewModel.panelWidth(for:)`, the single source the controller's `targetFrame(width:height:)` and the view's content `.frame(width:)` both use — 640 everywhere, 840 for the sidebar tools; a hard-coded content width squeezed the sidebar layout into 640 while the window was 840), and category switches animate: the panel resizes via `NSAnimationContext` (>60pt deltas) while the content crossfades with `.toolSwitch` (blurFade + top-anchored scale) driven by `.animation(.easeInOut(duration: 0.18), value: selectedCategory)` — matching durations keep window and content in sync. Panel height caps at 440 (`resizePanelToFit`); result lists frame at `maxHeight: 360` (chat messages at 280), and the search/category view sizes to its content (no fixed frame — an empty search is just the search bar, ~52pt). **Koltrast accents** (`Theme` in `Sources/Trast/UI/Theme.swift`): surfaces and interactive states stay native (system materials, `Color.accentColor` for selection/hover — amber on the selection tint read too loud and was reverted); `Theme.beak` amber (#F59F00, sampled from the app icon's beak/eye-ring) is a small FIXED accent on glyphs only — search magnifier, tools button glyph, ⌘-number badge numbers, calculator icon, favorite star. The bird wears one small bright accent; the UI follows the same ratio — don't spread amber over Settings or chat (chat bubbles still use the system accent), and don't tint the panel surface (a coal overlay read too brown; that experiment was reverted).
- **Launcher hotkey** (`GeneralSettingsView` / `HotkeyManager.openLauncher`): `KeyboardShortcuts.Name("openLauncher")`. The launcher shows results only when the query is non-empty (Spotlight behavior). Cmd+, opens Settings from the launcher.
- **Next Window hotkey** (`WindowSettingsView` / `HotkeyManager.nextWindow`): `WindowCycler` uses Accessibility to get the front app's windows, find the current main window, and raise the next one, so it works regardless of whether the system "Move focus to next window" shortcut is enabled or what keyboard layout is in use. It keys windows by CGWindowID (`WindowManipulator.cgWindowID`, the `_AXUIElementGetWindow` dlsym) and keeps a stable per-app round-robin order (`WindowCycler.cycleOrder`) across presses — the AX window list is app-defined and for some apps follows z-order (the raised window moves to the list front), and index-of-main+1 in such a list picks the same second window every press, degrading the cycle to toggling the top two windows of three or more. Closed windows drop out of the cached order; new ones append. Fallback (no resolvable IDs) is the old index+CFEqual path.
- **Next Display action** (`WindowAction.nextDisplay`, id `"nextDisplay"`): unlike other actions that flow through `LayoutEngine.frame(for:)` on a single screen, this one is intercepted in `CommandApplier.apply` (checked by `command.id == WindowAction.nextDisplay.commandID`) and handled by `moveToNextDisplay`, which finds the current screen via `WindowManipulator.screen(containing:)`, cycles to the next in `NSScreen.screens`, and uses `LayoutEngine.frameForNextDisplay` to preserve the window's relative position and size. The pure math is testable in `LayoutEngineTests`.
- **Export / Import** (`ConfigPorter`, app target): combines `CommandStore.commands` and `AppShortcutStore.shortcuts` into a single versioned JSON. Import calls `replace(with:)` on both stores, which clears old hotkey bindings and re-registers. Hotkey assignments themselves are not included (stored by KeyboardShortcuts in UserDefaults, keyed by `KeyboardShortcuts.Name`).
- App icon: drop a 1024x1024 PNG at `Resources/AppIconSource.png`, run `Scripts/make_icons.sh` (sips + iconutil generate `Resources/AppIcon.icns`), then rebuild — `package_app.sh` embeds it and sets `CFBundleIconFile`.
- Menu bar icon: drop a small monochrome (template-style) PNG at `Resources/MenuBarIcon.png`; `package_app.sh` bundles it and `StatusBarIcon` loads it at runtime (rendered as a template image, 18pt tall, falling back to the `rectangle.split.3x3` SF Symbol when absent).
- **Signing**: `package_app.sh` resolves the identity in order: `CODESIGN_IDENTITY` env → `Scripts/codesign-identity` file (git-ignored, first line) → ad-hoc. Ad-hoc signatures change on every rebuild and invalidate the Accessibility (TCC) grant — with a stable identity (self-signed "Trast" cert) the grant survives rebuilds. Fix per rebuild otherwise: `tccutil reset Accessibility com.trast.app`, re-toggle, relaunch.
- Opening System Settings panes uses `/usr/bin/open` via `Process` (`Accessibility.openSystemSettings()`), trying `x-apple.systemsettings:` then the legacy `x-apple.systempreferences:` scheme (this macOS build only registers the legacy one), then falls back to launching System Settings by bundle ID. `NSWorkspace.shared.open` fails to resolve these schemes when the app is launched from a terminal session.
- **App launching** (`LauncherController.installedAppItems`): the launcher shows all installed apps (from `AppScanner.cachedApps()`) in an "Applications" section, deduped against apps already in `AppShortcutStore` (by bundle ID or path). `AppScanner.refresh()` warms the cache on launch in a background queue. `AppScanner.startWatching()` (called at launch) puts `DispatchSourceFileSystemObject` watchers on the app directories so apps installed while Trast runs are picked up without a relaunch — events trigger a debounced (1s, so half-copied .app bundles are never scanned) background rescan that REUSES cached entries per bundle path (only new apps pay the Bundle/icon load) and posts `AppScanner.appsDidUpdate` when the list changed; `LauncherController` observes it and rebuilds `viewModel.items` if the panel is open. `LauncherItem.installedApp` carries an `NSImage` icon via `iconImage`; `LauncherRowView` renders `Image(nsImage:)` when available, falling back to SF Symbols.
- **Clipboard history** (`Clipboard/`): `ClipboardMonitor` polls `NSPasteboard.general.changeCount` every 0.5s via `DispatchSourceTimer`; on change reads `.fileURL` / `.tiff` / `.png` / `.string` types (in that order) and stores in `ClipboardStore` (versioned JSON at `~/Library/Application Support/Trast/clipboard.json`, max 100 items, pinned items never expire, configurable auto-clear). The launcher's Clipboard tab is the only clipboard UI — the `openClipboard` hotkey (registered in `HotkeyManager.registerAll`) calls `LauncherController.showClipboard()` (toggle: opens the launcher on the Clipboard tab). Search inside the tab matches full item content via `LauncherItem.searchText`; the standalone `ClipboardController` overlay was removed. Paste-on-select (in `LauncherController.pasteClipboardItem`) writes to `NSPasteboard.general` then posts `CGEvent` Cmd+V (virtualKey 9, `.maskCommand` flag). Settings in the Clipboard settings tab.
- **Snippet expansion** (`Snippets/`): `Snippet` model in Core (id, name, keyword, content, enabled; custom Codable with `decodeIfPresent` defaults). `SnippetStore` is versioned JSON at `~/Library/Application Support/Trast/snippets.json`. `SnippetExpander` creates a listen-only `CGEvent.tapCreate` on `.keyDown`; requires **Input Monitoring** permission (`CGPreflightListenEventAccess` / `CGRequestListenEventAccess`, prompted on first enable — a new permission distinct from Accessibility). Maintains a keystroke buffer; on each keyDown, appends the Unicode char (via `keyboardGetUnicodeString`) and checks for exact buffer == keyword match. The buffer resets on space/return/escape/tab, on any keyDown with Cmd/Option/Control held (pastest/select-all leaked their letter into the buffer), on any key that produces no text (arrows, F-keys, Home/End — cursor moved), on mouse clicks (global `NSEvent` monitor) and on frontmost-app changes (`NSWorkspace.didActivateApplicationNotification`); without these resets, residue from earlier typing makes `buffer == keyword` fail ("works on second try" symptom). On match: schedules injection on a background serial queue after a ~30ms settle delay (lets the final physical keystroke finish so synthetic events never race real ones), selects the typed keyword with `keyword.count` Shift+Left CGEvents (~2ms pacing between presses, ~6ms keyDown-to-keyUp gap — arrow-key events are safe to post back-to-back, unlike text-generating events; the sweep must stay under ~50ms or the highlight visibly crawls right-to-left before the paste on longer keywords), then (after a short phase gap) pastes the expansion in one shot: saves all pasteboard types, writes the resolved text to `NSPasteboard.general`, posts a synthetic Cmd+V, and restores the saved pasteboard ~250ms later; `ClipboardMonitor.suspendCapture`/`resumeCapture` bracket the override so neither the expansion nor the restore is captured into clipboard history (resume also syncs the monitor's changeCount). Selection+paste, not backspaces+typed text, for two reasons (TERMINALS EXCEPTED: `terminalBundleIDs` detection switches the erase to backspaces — arrow keys become escape bytes in terminals, so the Shift+Left sweep leaked visible "D"s; backspaces are safe there since a shell prompt has no autocomplete suggestion to eat): (a) address bars (Chrome/Safari omnibox) inline-autocomplete what you type and the gray suggestion is a live selection — the first backspace eats the suggestion instead of a typed char, leaving keyword residue (`!in` → `!https://…`); the Shift+Left selection covers the autocomplete and the paste replaces the whole thing, and (b) synthetic typing had to be paced ~12ms/char to stay above the app coalescing threshold, so long expansions visibly streamed in character by character; a paste lands in a single frame (also why multiline snippets are safe — typed Returns would submit forms). Keystrokes landing in Trast's own key window (launcher search, settings fields) are ignored so editing a keyword in Settings never fires the snippet. All injected events use a **private `CGEventSource`** (`CGEventSourceStateID(rawValue: -1)` — the `.private` case is not exposed in this SDK's Swift overlay) so physical keys held during expansion can't suppress them, and carry a magic tag in `eventSourceUserData` so the tap callback ignores its own output (without this, expansion text feeds back into the keystroke buffer and breaks the next match). Master toggle in General settings (`snippetsEnabledKey`, default false). Snippets CRUD in the Snippets settings tab.
- **Hyper key** (`Hyperkey/`): Caps Lock → ⌃⌥⇧⌘ (`HyperkeyEngine`; master toggle `hyperKeyEnabledKey`, default false; `hyperSymbolKey` shows ⌃⌥⇧⌘ as ✦). Caps Lock is not usable at the CGEvent level — each press emits one `flagsChanged` per lock TOGGLE and releases emit nothing — so press/release is detected with a passive `IOHIDManager` (keyboard devices, usage page 0x07 / usage 0x39; needs Input Monitoring, prompts via `CGRequestListenEventAccess` when `IOHIDManagerOpen` returns `kIOReturnNotPermitted`). An active session `CGEventTap` (flagsChanged + keyDown + keyUp) consumes the caps `flagsChanged` (lock never engages, lone tap does nothing) and, while caps is held, inserts the four modifiers into every event's flags — Carbon hotkey matching and recorders read event flags, so KeyboardShortcuts' `onKeyUp` dispatch and the recorder work unchanged. The tap and the `IOHIDManager` run on a DEDICATED thread's run loop (`runEngine`), never the main one — a busy main thread delays tap callbacks past the system's tap timeout, disabling the tap and lagging hyper detection ("hyper dies under heavy load while plain Carbon hotkeys keep working"); all engine state is engine-thread-confined, main only calls `start()`/`stop()` (setup/teardown handsake via semaphores + `stateLock`), and the callback re-enables the tap on `tapDisabledByTimeout`/`tapDisabledByUserInput`. **The keyboard lock/LED logic lives below the CGEvent layer** (consuming the flagsChanged does not stop the LED), so the engine also remaps Caps Lock → F18 at the HID driver level via `/usr/bin/hidutil property --set UserKeyMapping` (`0x700000039`→`0x70000006D` — page<<32|usage, 9 hex digits; a wrong Src silently no-ops and caps keeps toggling the lock) on start and reverts (empty mapping) on stop — the tap consumes the resulting F18 keyDown/keyUp so apps never see a stray key. hidutil needs no root; mappings reset on reboot, so a crash can leave caps as F18 until the next toggle/reboot, and the remap REPLACES any personal Caps Lock remap set in System Settings (restores to factory, not previous). If the HID monitor can't open (no Input Monitoring) the engine tears the whole tap down so Caps Lock keeps working normally. Known limitation: external keyboards on macOS 26+ don't pass CGEventTaps, so the mutation can't reach their keyDowns — hyper detection still works but hotkeys only fire from the built-in keyboard (fix would need IOKit HID seizure like feedthejim/hyperkey). Synthetic per-modifier `flagsChanged` events (private `CGEventSource`, `eventSourceUserData` tag) keep session modifier state consistent for other apps. Requires Accessibility + Input Monitoring (warnings in the Hyper Key section of General settings). Must quit Hyperkey.app first (two active remappers conflict); its driver-level caps→⌘ HID remap survives until reboot or `hidutil property --set '{"UserKeyMapping":[]}'` (during that window caps produces ⌘ flagsChanged, which the tap passes through with hyper inserted — still works since ⌘ is part of the combo). ✦ display: `HotkeyDisplay` (Core, pure, tested) collapses the `⌃⌥⇧⌘` prefix when carbonModifiers == the four Carbon bits; labels use `Shortcut.hyperDescription` (`Hotkeys/HotkeyLabel.swift`) in `CommandListView`, `AppShortcutListView`, `LauncherView`. `HotkeyRecorderView` (Settings) replaces `KeyboardShortcuts.Recorder` at all sites — same `setShortcut`/`getShortcut` storage, but ✦ rendering (the package's `RecorderCocoa` hardcodes `"\(shortcut)"` and its `Bundle.module` strings can't ship in the packaged app) and `performKeyEquivalent` interception so menu equivalents (⌘W etc.) record instead of firing. Mirrors RecorderCocoa rules (bare Tab bubbles, Esc cancels, Backspace/Delete clears, shift-only beeps); CANNOT pause hotkey dispatch or warn on system-taken combos (`isPaused`/`isTakenBySystem`/`shortcutByNameDidChange` are internal to the package). The menu bar still uses SwiftUI `.keyboardShortcut` (system-rendered glyphs — no ✦ there).
- **Launcher calculator** (`Calculator/`, core `Calculator.swift`): queries in the launcher's All category parse to math (`MathEvaluator`, a recursive-descent parser over `+ - * / % ^ ( )` with unary ±, right-associative `^`, `×÷`/Unicode minus, comma digit separators; bare numbers rejected so plain queries don't produce calculator rows), unit conversions (length/mass/volume/speed tables + affine temperature; `" to "`/`" in "` separators, the latter tried last-separator-second because `in` is also the inch unit — `"5 in in cm"`), and currency. The result inserts as a `LauncherItem.calculatorResult` above all other sections; Enter copies and closes (HUD "Copied"). Currency takes the rates table as an `@autoclosure` parameter so the network store is only touched when the query contains a currency token/symbol — `ExchangeRateStore` (app target) fetches frankfurter.dev (ECB daily rates, no API key), caches to `~/Library/Application Support/Trast/rates.json`, refreshes at most once per day (10-min retry throttle on failure), and is warmed at launch from `AppDelegate` — without the launch warm-up a cold start has no table for the first seconds; a cache whose base doesn't match the `baseCurrency` setting is unusable until refreshed. Bare amounts (`"25 eur"`) convert to the base currency; bare units (`"5 km"`) only convert when they cross the metric/imperial counterpart and the opposite system is preferred (`preferredUnitsKey`), else no row. Settings: base-currency picker and metric/imperial picker in General (`baseCurrencyKey`, default USD; `preferredUnitsKey`, default metric). Tests in `CalculatorTests`.
- **Launcher tools view (unified)**: the launcher has ONE surface for browsing: the tools view (↓, Tab, or the list button in the search bar, all from an empty search; `showRecentActivity`). It lists ONLY the tool rows — the old favorites and recents tiers are gone (search still finds everything; favorites remain row stars + the options modal, and UsageTracker ordering still applies inside category lists like Apps). `Category.toolCases`: **Apps first**, then Clipboard (if its tab is on), Color Picker, Snippets (if on), Scratchpad, Text Transformer, AI Chat. Cmd+1..n opens the tool at that `toolCases` position (`selectCategoryByIndex`) — the same numbers the rows badge with. Esc steps back: category → tools view → close. The launcher always opens as a bare search bar (Spotlight-style) — the tools view is reachable only via ↓/Tab/the list button (the old "On open" Compact/Full picker, `AppSettings.launcherOpenViewKey` and `launcherOpensToTools`, was removed). To add a tool: add a `Category` case, insert it in `toolCases`, and give it either a mode view in `LauncherView` (Scratchpad-style, which also needs the `LauncherController` key-monitor carve-out, a `HotkeyManager` hotkey, and a Settings home) or nothing extra if it's a plain list category like the Clipboard (items flow through `recentItems(for:)` + `includesInCategory`).
- **Launcher favorites & recent activity**: ↓ with an empty All search opens the tools view (`LauncherViewModel.showRecentActivity`, `showsRecentActivity`) — tool rows only, no favorites/recents tiers. `filtered` is always the sections flattened, so the selection walks the display order. Tools are NOT favoritable (`isFavoritable` excludes `.toolEntry`; `.colorEntry` and `.clipboardEntry` too). Favorites are `LauncherItem.id` strings in `FavoritesStore` (UserDefaults key `launcherFavorites`); the ViewModel mirrors them in `@Published favorites` so toggles re-render — they surface as the row star and the options-modal toggle, nothing more. Right-click a row → "Options…" context menu or ⌘K on the highlighted row → `showOptionsForSelectedItem` sets `viewModel.optionsItemID`, and `LauncherView.optionsModal` renders a MODAL over a scrim (no NSMenu): favorites toggle, "Add as Shortcut" for plain installed apps (one click — `AppShortcutStore.add(app.appShortcut)`, name autofilled, `refreshItems()` rebuilds, and the modal stays on the row's NEW appJump id so the hotkey can be recorded), a `HotkeyRecorderView` for shortcut/command/action rows, and Remove Shortcut for shortcut-backed rows. While the modal is open the key monitor passes all keys through to it (the recorder needs raw keystrokes) except Esc/⌘K which close it; favorite toggles go through `LauncherViewModel.toggleFavorite(id:)`. Color entries carry their own context menu instead (Copy Hex/RGB/HSL, Remove Color). Text Transformer, AI Chat, and Color Picker are also searchable via `visibleCases` (categoryEntry items). Pressing ↓ when results already exist just moves the selection; typing re-ranks, and clearing the text back to empty still shows the tools view until reset (the flag clears on panel reset).
- **Color Picker** (`ColorPicker/`): `SavedColor` (Core: id, hex "#RRGGBB", createdAt) + `ColorFormats` (Core, pure, tested — normalize/parse/hex/rgb/hsl strings; NSColor is NOT imported in Core, so the app-side `ColorStore.hexString(from:)`/`nsColor(for:)` bridge to AppKit, blending alpha over white). `ColorStore` (app target, versioned JSON at `~/Library/Application Support/Trast/colors.json`, newest first, re-picking a stored hex moves it to top, capped at 200). The tool is a plain list category like Clipboard: `recentItems(for: .colorPicker)` = the "Pick Color from Screen" `LauncherAction.pickColor` row + saved colors as `.colorEntry` rows (swatch via `LauncherIconCache.colorSwatch`, cached by hex); Return copies hex (HUD), the row context menu copies rgb/hsl and removes. Picking runs `NSColorSampler` (`LauncherController.pickColorFromScreen`): the panel closes first (the eyedropper samples the screen), on a pick the color is saved (HUD "Saved #…") and the launcher reopens on the list. `HotkeyManager.openColorPicker` → `showColorPicker()` (toggle, same shape as the other tool hotkeys); recorder + delete-all live in the Color Picker settings tab.
- **Scratchpad notes**: the Scratchpad is deliberately not a notes app — `Note` (Core: text + timestamps, `excerpt` for the one-line list preview), `NotesStore` (app target, versioned JSON at `~/Library/Application Support/Trast/notes.json`, ordered updatedAt-desc, `@Published` so the launcher view re-renders; disk writes debounced 0.5s since typing updates per keystroke). The editor always has a current note — deleting the last one produces a fresh empty note (`delete`/`deleteAll` both guarantee non-empty); the current note id persists in UserDefaults key `scratchpadCurrentNoteID`. Legacy single-blob scratchpad text (UserDefaults `AppSettings.scratchpadTextKey`) migrates to the first note once (guard flag `scratchpadNotesMigrated`). The tool is a two-pane layout: a persistent notes sidebar (compact rows of excerpts + relative dates, whole-row click to open, right-click → Archive/Delete) beside the TextEditor bound to `NotesStore.currentNote` via a get/set Binding; the sidebar header toggles Notes | Archive (`notesSidebarShowsArchive`, archived rows right-click → Unarchive/Delete; `Note.isArchived`, Codable default false). The scratchpad branch of the `LauncherController` key monitor intercepts only Esc, Tab, and ⌘N — arrows/typing reach the editor. Editor footer: New (⌘N), Copy, Delete-with-confirm. The editor never edits an archived note (`currentNote` filters `isArchived`; archiving the last active note creates a fresh one). Settings' Scratchpad tab has "Delete All Notes" with its own inline confirm.
- **Text Transformer** (`TextTransformer/`, core `TextTransform.swift`): replaces the frontmost app's selected text with a transformed version (upper/lower/title/sentence/camel/pascal/snake/kebab/constant/toggle). Entering the tool (`selectCategory(.textTransformer)` → `LauncherController.enterTextTransformer`) captures the selection in two stages: (1) `TextTransformerController.axSelectedText` reads `kAXSelectedTextAttribute` of the system-wide focused element — no events, no pasteboard, works while the panel is open; (2) apps that don't expose AX selections (Terminal, some Electron views) fall back to `captureViaPasteboard`: the panel is HIDDEN first (posted keyboard events go to the app owning the key window — Trast while the panel is up — which is why a plain Cmd+C while the panel is open never reaches the target app and always read as "Nothing selected"), then a synthetic Cmd+C (private `CGEventSource`, snippet-expander injection approach) with the pasteboard saved/restored and the changeCount checked to detect "no selection". Applying (Return or row click → `LauncherController.applySelectedTransform`) closes the panel FIRST (matching the proven paste path), writes the transformed text, posts Cmd+V after a 50ms settle, restores the pasteboard ~250ms later, all bracketed by `ClipboardMonitor` suspend/resume — clipboard and history untouched. Word extraction handles camel humps and acronym boundaries (`XMLHttpRequest` → xml_http_request). Key handling is the transformer branch of the `LauncherController` monitor (arrows/Return/Esc/Tab; other keys swallowed). Its hotkey lives in Settings → Text Transformer (`HotkeyManager.openTextTransformer`, toggle via `showTextTransformer`). The transformation list is user-configurable: order (`AppSettings.transformOrderKey`) and disabled set (`transformDisabledKey`), read as `AppSettings.orderedTransforms` (unknown stored rawValues dropped, new transforms appended enabled) and loaded into `LauncherViewModel.transforms` on tool entry — the tool shows exactly that list; all disabled shows an empty state.
- **AI Chat** (`AIChat/`): `ChatMessage`/`ChatDiscussion` models in Core (custom Codable with defaults; discussion `title` = first user message excerpt, tested). `ChatStore` (versioned JSON at `~/Library/Application Support/Trast/chats.json`, updatedAt-desc, debounced saves, current discussion id in UserDefaults `chatCurrentDiscussionID`; the current discussion is created on the first message). `ChatService` — BYOK adapter with three request shapes: OpenAI-compatible (OpenAI/Mistral/OpenRouter `/chat/completions`), Anthropic (`/v1/messages`, `anthropic-version` header, max_tokens 1024), Google (`models/{model}:generateContent`, `x-goog-api-key`); **non-streaming** — one request per turn; model from `AppSettings.aiModelKey` (empty → `defaultModel(for:)`; free text since model names age fast). The API key lives in a **file** (`APIKeyStore` at `~/Library/Application Support/Trast/aikey`, permissions 600) — a Keychain item anchors its ACL to the creating binary's signature, so with the self-signed dev identity every rebuild looks like a different app and macOS demanded the login password on every read. One-time migration from the UserDefaults placeholder era (`aiAPIKeyKey`). The Keychain era item (service "com.trast.app") is deliberately NEVER touched — reading it triggered a login-password prompt per rebuilt binary, so it is left in the login keychain for the user to remove manually if they care. The Settings SecureField binds through `APIKeyStore` directly. UI in `LauncherView.aiChatTool`: header (title, ⌘N new, expand toggle), message bubbles (`ChatBubbleView` — user accent, assistant gray), input row (Return sends), inline error line, "Thinking…" state; previous discussions are a persistent SIDEBAR beside the conversation (`LauncherView.chatSidebar`, same shape as the Scratchpad's notes sidebar: compact rows of titles + relative dates, whole-row click to open, right-click → Archive/Delete, header Chats | Archive toggle — `ChatDiscussion.isArchived`, Codable default false; archived discussions never auto-open) Copy affordances: the header has a copy-transcript button ("You: …\n\nAI: …" pairs), and assistant bubbles reveal a copy button on hover. **Markdown rendering**: assistant bubbles parse via `ChatMarkdown` (Core, pure, tested — block parser: fenced code with language tag, ATX headings, bullet/ordered lists with lazy continuation, blockquotes, GFM pipe tables (header + `---` delimiter row with `:---:` alignment, `\|` escapes, rows padded/truncated to header width), soft-wrapped paragraphs; NOT CommonMark: no nesting/setext) into `ChatMarkdownBlock` views (AIChat/ChatMarkdownView.swift — code blocks and wide tables scroll horizontally, tables render as a SwiftUI `Grid` with a full-width header divider via `Divider().gridCellUnsizedAxes(.horizontal)`, lists indent, quotes get a bar); inline styling (bold/italic/code/links) rides `AttributedString(markdown:)` with `.inlineOnlyPreservingWhitespace` (`ChatMarkdown.inlineAttributedString`, plain-string fallback). User messages render verbatim; the copy button and transcript copy keep the RAW markdown. Key handling in the aiChat branch of the `LauncherController` monitor: Cmd+N starts a new discussion; typing passes through to the message field, but Return is intercepted (sends via `LauncherViewModel.sendChatMessage`) and **Shift+Return appends a newline to the draft — macOS fires onSubmit for Shift+Return too, so the event must be swallowed before the field**; the composer draft/send state (`chatInput`/`chatSending`/`chatError`) lives in the VIEW MODEL (not view @State) so the monitor can drive it and the panel-height LayoutSignature can track the vertically growing input (`TextField(axis: .vertical)`, `.lineLimit(1...6)`); history mode swallows typing. Settings → AI Chat: hotkey, provider, model, key, delete-all-discussions.
- **Edge gap presets**: the gap setting uses a segmented picker (Small=10px, Medium=20px, Large=40px, Extra Large=60px) instead of a raw px input. The gap is applied via `LayoutEngine.usableArea(in:gap:)` which insets the `visibleFrame`. `LayoutEngine.Request` also has an `interGap` parameter (defaults to 0) for inter-window gaps, but it is not currently passed by `CommandApplier` (revisit later).
